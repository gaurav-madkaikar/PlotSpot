# 33. Trailers, creative credits and cache upgrades

## The data flow

Opening a movie uses the existing `/api/movies/{id}` route. A fresh saved record with `presentation_version=1` is returned from SQLite. Older records get one TMDB enrichment read when the provider is available. Provider failure serves the last saved movie.

The detail request now asks TMDB for `append_to_response=credits,videos`. This folds the credits and video results into the movie response; it does not issue a separate request for every actor or video. The language configuration request is still shared through the provider's in-memory cache. Bulk imports using `enrich=True` continue to request search metadata without videos.

`movie_presentation.py` selects a trailer and maps exact crew jobs. `movie_metadata.py` attaches those values to the optional metadata. Pydantic validates them, SQLite preserves them, and Zod validates the frontend response. `movie-trailer.tsx` displays the player; `MovieCast` displays the creative team.

## Exact roles, not guesses

| TMDB job | Displayed credit |
| --- | --- |
| Writer | Writer |
| Screenplay | Screenplay |
| Story | Story |
| Original Music Composer | Composer |
| Director of Photography | Cinematographer |

A Music Editor is not automatically the composer, and a Camera Operator is not automatically the cinematographer. Different writing roles stay distinct. Duplicate name/role pairs are removed; the list is capped at twenty.

## Trailer selection and playback

Only YouTube records explicitly typed `Trailer` are eligible. The identifier must contain exactly eleven allowed characters. Official trailers rank first, then English-language records; the identifier provides deterministic ordering for ties. Teasers, clips, unsupported sites and malformed records are omitted. Video selection considers at most five hundred records.

The frontend constructs a URL on `www.youtube-nocookie.com` from that validated identifier. No arbitrary provider URL is embedded. The iframe is created after Watch trailer is clicked, and removed when the native dialog closes. Escape closes the dialog, the browser returns keyboard focus, and a Watch on YouTube link is available if embedding is unavailable. Trailers may reveal story details.

## Questions and answers

**Why use a presentation marker instead of checking whether a trailer exists?** A movie can legitimately have no supported trailer. A marker records that we attempted the enrichment, preventing a new request on every visit just because the result is empty.

**Are trailers generated by the LLM?** No. These are provider metadata, just like cast names. No RAG or model invocation is needed.

**What is cached?** The provider caches raw HTTP responses in memory for its configured TTL. SQLite stores normalized movie metadata, including creative credits, selected trailer and presentation marker; its freshness window is seven days. The browser also retains validated movie responses through TanStack Query. Each cache serves a different layer.

**Why keep new fields optional in Zod?** Old backend responses and already-open browser tabs can still contain older metadata. New arrays default to empty, and components also handle an absent array in already-cached objects.

**Does one enrichment rewrite the semantic index?** No. This updates the selected movie's metadata in SQLite. The existing 1,500-vector discovery snapshot remains separate.

**What happens when an optional video field is malformed?** The trailer is omitted while core movie metadata remains usable. If the whole provider request fails, the existing last-good fallback applies.
